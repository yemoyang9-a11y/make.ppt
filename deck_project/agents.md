# Agents

## 문서 목적

이 문서는 발표 자료를 만들 때 누가 어떤 일을 맡는지 정리하는 문서입니다.  
사람이 직접 맡는 역할과 AI에게 맡길 수 있는 역할을 쉽게 구분합니다.

## 업무 목적

- 발표 자료의 방향을 빠르게 정리합니다.
- 필요한 정보, 디자인, 슬라이드 순서를 미리 맞춥니다.
- PPT 파일을 만들기 전에 생각을 먼저 정리합니다.
- 초보자도 다음 작업을 쉽게 이어갈 수 있게 합니다.

## 기본 규칙

- 아직 PPT 파일은 만들지 않습니다.
- 어려운 전문 용어는 쉬운 말로 바꿔 씁니다.
- 모르는 내용은 추측하지 않고 `[확인 필요]`라고 표시합니다.
- 숫자, 고객 사례, 시장 자료는 출처를 적습니다.
- 한 슬라이드에는 한 가지 핵심 메시지만 담습니다.
- 전체 덱에서는 이미지나 시각 자료를 최소 3개 정도 활용하는 것을 권장합니다.
- 이미지가 필요한 영역은 `$imagegen` 스킬을 활용해 생성한 뒤 `assets/imagegen/` 폴더에 보관할 수 있게 합니다.
- 외부 브랜드 로고, 실제 고객사 로고, 허가받지 않은 제품 화면은 이미지에 넣지 않습니다.

## 역할 초안

### 1. 기획 담당

해야 할 일:

- 발표의 목적을 정합니다.
- 듣는 사람이 누구인지 정합니다.
- 발표 후 듣는 사람이 어떤 행동을 하길 원하는지 정합니다.

결과물:

- `business_context.md`
- `deck_brief.md`

### 2. 자료 조사 담당

해야 할 일:

- 시장, 고객, 경쟁사, 문제 상황을 조사합니다.
- 믿을 수 있는 자료인지 확인합니다.
- 중요한 숫자와 근거를 정리합니다.

결과물:

- `references/` 폴더 안의 참고 자료
- `business_context.md` 안의 근거 메모

### 3. 메시지 정리 담당

해야 할 일:

- 발표에서 꼭 말해야 할 핵심 문장을 정합니다.
- 슬라이드마다 제목과 메시지를 정리합니다.
- 너무 긴 내용을 짧고 쉽게 줄입니다.

결과물:

- `deck_brief.md`

### 4. 디자인 담당

해야 할 일:

- 색상, 글꼴, 이미지 느낌을 정합니다.
- 슬라이드가 깔끔하고 읽기 쉬운지 확인합니다.
- 표와 그래프를 보기 쉽게 정리합니다.

결과물:

- `design.md`
- `assets/` 폴더 안의 이미지, 아이콘, 로고 후보

### 5. 이미지 생성 담당

해야 할 일:

- 이미지가 필요한 슬라이드를 찾습니다.
- 직접 촬영한 사진이나 회사 자료가 없을 때 `$imagegen` 스킬로 대체 이미지를 만들 수 있는지 검토합니다.
- 이미지 프롬프트를 작성합니다.
- 생성된 이미지를 제안서 분위기와 맞는지 확인합니다.
- 최종으로 사용할 이미지는 `assets/imagegen/` 폴더에 저장할 수 있게 정리합니다.

사용 기준:

- 사진, 배너, 업무 장면, 제안서용 비주얼처럼 **비트맵 이미지**가 필요한 경우 `$imagegen`을 사용합니다.
- 단순 아이콘, 선, 박스, 흐름도처럼 PPT 안에서 직접 만들 수 있는 요소는 굳이 이미지로 만들지 않습니다.
- 프로젝트에 실제로 넣을 이미지는 기본 생성 위치에만 두지 않고, 작업 폴더 안의 `assets/imagegen/`로 옮겨 관리합니다.

권장 이미지 후보:

- 표지 또는 첫 장: AI 자동화 컨설팅의 전체 분위기를 보여주는 대표 이미지
- 현재 상황 슬라이드: 반복 업무에 지친 대표 또는 운영팀의 업무 장면
- 4주 진행 방식 슬라이드: 진단, 설계, 연결, 적용을 보여주는 업무 시스템 이미지
- 적용 예시 슬라이드: 고객 문의, 보고서, 제안서가 자동으로 정리되는 장면
- 기대 효과 슬라이드: 시간이 절감되고 업무가 정돈된 느낌의 이미지

이미지 생성 시 피해야 할 것:

- 특정 외부 브랜드 로고
- 실제 고객사 이름이나 민감 정보
- 읽기 어려운 작은 글자
- 과장된 미래 도시나 로봇 이미지
- 제안서 주제와 관계없는 장식 사진

결과물:

- `deck_brief.md` 안의 이미지 필요 영역 표시
- `assets/imagegen/` 폴더 안의 최종 이미지 후보
- 이미지별 프롬프트 메모

### 6. 검토 담당

해야 할 일:

- 내용이 발표 목적과 맞는지 확인합니다.
- 틀린 정보나 빠진 내용을 찾습니다.
- 초보자가 읽어도 이해되는지 확인합니다.
- 이미지가 특정 브랜드나 실제 고객 정보를 침해하지 않는지 확인합니다.

결과물:

- 수정 의견
- `[확인 필요]` 목록

## AI에게 맡길 수 있는 일

- 긴 문장을 짧게 줄이기
- 슬라이드 제목 후보 만들기
- 발표 흐름을 자연스럽게 다듬기
- 표나 그래프 설명을 쉽게 바꾸기
- 디자인 방향을 문서로 정리하기
- 이미지가 필요한 슬라이드 찾기
- `$imagegen`용 이미지 프롬프트 초안 만들기
- 제안서 분위기에 맞는 이미지 후보 생성하기

## 사람이 꼭 확인해야 할 일

- 실제 회사명, 제품명, 고객명
- 매출, 비용, 시장 규모 같은 숫자
- 법적 표현, 보안 정보, 민감한 정보
- 최종 발표 대상과 발표 시간
- 생성 이미지가 실제 고객사 자료처럼 오해되지 않는지 여부
- 이미지에 사용해도 되는 로고, 화면, 인물, 상표 범위

## 현재 멈춤 기준

문서 초안 작성이 끝나면 다음 작업으로 넘어가지 않습니다.  
사용자가 확인한 뒤에만 다음 단계인 자료 보강, 디자인 구체화, PPT 제작 등을 진행합니다.
